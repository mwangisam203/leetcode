When writing Big O:

Ignore constants.
Keep only the fastest-growing term.

O(5)        → O(1)

 ## A small cheat sheet


| Code Pattern                | Complexity |
| --------------------------- | ---------- |
| `arr[5]`                    | O(1)       |
| One loop over `n` items     | O(n)       |
| Two separate loops over `n` | O(n)       |

Topics about DSA

Order of topics
Go roughly in this sequence — each builds on the last:

Arrays & Strings — two pointers, sliding window, prefix sums
Hashing — hash maps/sets for O(1) lookups (this unlocks a huge chunk of "easy" problems)
Linked Lists — traversal, reversal, fast/slow pointers
Stacks & Queues — monotonic stacks, parentheses matching, BFS prep
Recursion & Backtracking — before trees, since trees are recursive by nature
Trees — traversals (in/pre/post-order), BST properties, then binary tree problems
Graphs — BFS, DFS, then topological sort, union-find
Heaps / Priority Queues — top-K problems, merging
Dynamic Programming — save for last; it's the hardest and benefits from everything above (especially recursion and arrays)
Greedy & Intervals — can be woven in anytime after arrays

Week-by-week

Days 3–4: Sliding window (max subarray sum, longest substring without repeats)
Days 5–6: Prefix sums (subarray sum equals K, running sum)

The actual signal-to-pattern mapping
This is the part people skip writing down, and it's the highest-leverage thing to memorize:

| If you see... | Think... |
|---|---|
| Sorted array + find pair/triplet | Two pointers |
| Substring/subarray + "longest/shortest/contains" | Sliding window |
| Need subarray sum repeatedly | Prefix sum |
| "Find if exists" in unsorted data, need O(1) lookup | Hash map/set |
| Sorted array, or "find minimum X such that condition holds" | Binary search (on array or on answer space) |
| Linked list + "find middle/cycle/kth from end" | Fast/slow pointers |
| Need "next greater/smaller element" | Monotonic stack |
| Matching brackets/nested structure | Stack |
| "All possible combinations/subsets/arrangements" | Backtracking |
| Tree + "path" or "depth" | DFS (recursion) |
| Tree + "level by level" | BFS |
| Graph + "shortest path, unweighted" | BFS |
| Graph + "is there a path/connected" | DFS or Union-Find |
| Graph + "ordering with dependencies" | Topological sort |
| "Kth largest/smallest" or "top K" | Heap |
| Overlapping subproblems + optimal substructure + "min/max/count ways" | DP |
| "Maximize while avoiding conflicts" (intervals, scheduling) | Greedy |


General pattern-recognition cues:

"Find duplicate" + "no extra space allowed" → think sorting, or Floyd's cycle detection if values are in range [1,n].
"Find duplicate" + space is fine → set or Counter, almost always the right first answer.
"Min/max of every window" → monotonic deque, not a fresh loop per window (that's O(n·k), too slow).
Built-ins (min(), set(), Counter) are fine to use in interviews after you've shown you understand the manual version — don't lead with them if the interviewer is testing fundamentals.


Complexity cheat notes:

Set/dict operations (in, add, lookup) are O(1) average, O(n) worst case (hash collisions) — mention average case unless asked.
Sorting is O(n log n) — the moment you sort, that becomes your floor even if the rest of the algorithm is O(n).
"O(1) space" claims should ignore input/output storage but must count any extra structure you allocate (a set(), a new list, etc.).


Common pitfalls:

Forgetting the empty-array edge case (if not arr: return None).
Using min(arr) inside a loop (recomputes every time — O(n²) instead of O(n)). Track the running min instead.
Confusing "has duplicates" (any) with "find the duplicate" (which one) with "find all duplicates" (all of them) — these need different tools (#7 vs #10 vs #8).
With Floyd's algorithm, forgetting it only applies to the specific "n+1 values in [1,n]" setup — it is not a general duplicate-finder.


NOTES: WHAT TO PAY ATTENTION TO

Choosing the right structure:

set — membership only, no values attached (contains duplicate, intersection)
dict — key → value mapping (two sum: value → index)
Counter (subclass of dict) — key → count, with useful extras (.most_common(), arithmetic between Counters)
defaultdict — dict that auto-initializes missing keys (group anagrams, adjacency lists) — avoids if key not in d: d[key] = [] boilerplate
